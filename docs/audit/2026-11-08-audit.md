# Code Audit and Repair Sweep — 2026-11-08 (0.6.2)

> **Scope**: every line of `src/`, the test, fuzz and bench files, both CI
> workflows, and the part of the vendored `vani-core` that polyomino calls.
> Covers the M3 and M4 code that the
> [2026-05-26 P(-1) pass](2026-05-26-audit.md) predates. Follows
> [first-party-standards § Security Hardening](https://github.com/MacCracken/agnosticos/blob/main/docs/development/first-party/first-party-standards.md).
>
> **Result**: no CRITICAL or HIGH findings, and no memory-safety defect. Three
> MEDIUM and nine LOW findings, plus one project-rule violation, all fixed with
> regression tests. The simulation's core tables were correct.

## Severity key

CRITICAL (remote / privilege escalation) · HIGH (moderate effort) ·
MEDIUM (specific conditions) · LOW (defense-in-depth). Most findings here are
correctness rather than security, so MEDIUM and LOW also reflect the effect on
a player.

## Method

- **Read everything**, against the project's hard rules and the documented
  mechanics. Each piece's four rotation states, both SRS kick tables, the
  scoring tables and the gravity curve were checked by hand against the
  published values in row-down coordinates. All matched.
- **Reproduced each defect before fixing it**, in a scratch copy with the
  framebuffer path and audio card neutered, so no run could touch a real
  display or speaker.
- **Toolchain checks**: `CYRIUS_BOUNDS=1 CYRIUS_POISON=1` builds of the test
  suite and the fuzz target, `cyrius lint --strict`, and the aarch64 build under
  `qemu-aarch64`, with syscalls traced via `-strace`.
- **Randomized play**: `tests/cyrius-polyomino.fcyr` (new, see TEST-1).
- **Mutation checks**: each repair was broken on purpose to confirm a test
  fails. 18 mutations, all caught.
- **End to end**: the real game driven through a pseudo-terminal for the
  raw-mode paths that unit tests cannot reach.

## Checklist

### 1. Input validation

External inputs are the two command-line arguments and stdin bytes. Arguments
went to `atoi` unvalidated (LOW-7). The stdin decoder never over-reads, but
misread a split escape sequence (MED-2).

### 2. Buffer safety

Every `var buf[N]` and heap allocation reviewed: `input.cyr` termios and read
buffers, `tick.cyr`, `hud.cyr` digits (20 ≥ the 19 digits of an i64),
`world.cyr` queue (at most 13 live of 16), `audio.cyr` sw-params (136 =
`SWP_SIZE`), render buffer (longest cue 61,440 of 65,536 B), `present.cyr` row
buffer. **OK**, confirmed by the bounds and poison runs.

### 3. Syscall review

Three unchecked returns (LOW-4, LOW-5, LOW-6) and two raw syscall numbers that
are wrong on aarch64 (MED-3).

### 4. Pointer validation

All heap pointers are internally allocated. Piece types and rotations stayed in
range across the fuzz sweep. **OK.**

### 5. Command injection

No `sys_system` / `exec_*`, and nothing spawns a process. **PASS.**

### 6. Path traversal

All file paths are hardcoded. **PASS.** The M5 save file remains the first
untrusted-file surface and needs its own pass.

### 7. Known CVE review

No third-party parser, network stack or codec. `vani-core` is at its latest
release (1.2.10), and the pin at 6.7.18 carries the toolchain's own security
fixes. The only supply-chain gap was in CI (LOW-9). **PASS.**

## Findings

| ID | Severity | Finding | How it was shown | Status |
|----|----------|---------|------------------|--------|
| MED-1 | MEDIUM | A piece could be held up forever. The lock-reset budget and timer refilled whenever the piece was airborne, so kicking up and falling back onto the same row restarted them. | A T alternating kick-up rotations survived 2,000,000 frames (over nine hours) without locking. | **Fixed**: bounded extended placement. Only a new lowest row refills the budget, every move spends it after touchdown, and a spent budget locks on landing. The same sequence now locks in 432 frames. |
| MED-2 | MEDIUM | An arrow-key sequence split across two reads quit the game, because `input_poll` treated `ESC [` with its final byte unread as a lone ESC. It needs only a queue of 11 repeats, or a slow link. | `ESC [` on stdin set the quit bit, as did 32 bytes ending mid-sequence. | **Fixed**: pure `input_decode` handles split sequences; a lone ESC still quits. |
| MED-3 | MEDIUM | Two raw x86_64 syscall numbers are wrong on aarch64: `syscall(201)` runs `listen` instead of `time`, so every game dealt the same pieces, and `syscall(8)` is not `lseek`, which broke the framebuffer blit. | `qemu-aarch64 -strace` showed `listen(0, …) = -22`, and `syscall(8, …)` returned `-14`. | **Fixed**: `clock_gettime` for the seed, stdlib `sys_lseek`. Both traced correctly under qemu. |
| LOW-1 | LOW | With no terminal, `wait_key` spun forever on top-out, while its comment claimed it returned at once. | Interactive mode with `</dev/null` was still running after the timeout. | **Fixed**: returns at once when raw mode is not active. |
| LOW-2 | LOW | A key still held at top-out dismissed the game-over screen immediately. | One pending byte ended the wait on its first poll. | **Fixed**: a 45-frame grace window ignores keys. |
| LOW-3 | LOW | A piece kicked wholly above the well locked with all four cells discarded, and play continued. Reachable with two ordinary rotations. | Cell count unchanged after the lock, state still playing. | **Fixed**: guideline lock out ends the game. |
| LOW-4 | LOW | `fb_present_open` ignored both ioctl results, assumed 32 bpp, and computed negative offsets on a screen smaller than the surface. | By inspection, then a regular file standing in for `/dev/fb0`. | **Fixed**: any of these leaves the framebuffer unavailable rather than drawing garbage. The stand-in file received 0 bytes. |
| LOW-5 | LOW | `input_init` ignored the `TCSETS` result and marked raw mode active anyway. | By inspection. | **Fixed**. |
| LOW-6 | LOW | The PPM dump opened without `O_TRUNC`, leaving a stale tail, and the smoke exited 0 even when it could not write the file. | A 500,000-byte file stayed that size; a missing `build/` exited 0. | **Fixed**: truncates, checks the pixel write, exits 1. |
| LOW-7 | LOW | Non-numeric arguments were read as 0, so `--help` ran a 0-frame smoke and overwrote the PPM. | `--help` exited 0 and wrote a file. | **Fixed**: validated first; bad usage prints help to stderr and exits 2. |
| LOW-8 | LOW | Ctrl-C did nothing, because raw mode turns signals off and byte 3 was unmapped. | Byte 3 decoded to no action. | **Fixed**: Ctrl-C quits. |
| LOW-9 | LOW | CI piped the installer from the moving `main` branch and verified neither the lockfile nor the audit sweep. | By inspection. | **Fixed**: installer taken from the pinned tag; `deps --verify` and `cyrius audit` run in CI. |
| POL-1 | Rule | The trademarked title appeared in an enum name, comments, test labels and two docs, against ADR 0001. | `grep`. | **Fixed**: generic "quad". The game binary was byte-identical after the rename. CI now fails on any return. |
| TEST-1 | Gap | The fuzz target was an empty stub. | By inspection. | **Fixed**: random play checked against 17 invariants, including cell conservation and replay determinism. |
| DOC-1 | Docs | Stale or wrong comments: `das.cyr` claimed a steady key-repeat stream, `piece.cyr` and `srs.cyr` still described M1-era plans, `world.cyr` gave the wrong struct size, and the README status was 0.5.0. | By inspection. | **Fixed**. |
| CLEAN-1 | Cleanup | `world_soft_drop` had no callers and no tests, and locked instantly, unlike the real soft drop. | `grep`. | **Removed**. |

## Accepted and deferred

| ID | Note |
|----|------|
| INFO-1 | The well has no hidden rows, so a cell locking above row 0 is dropped even when others land. A real buffer zone would be a feature; the deviation is documented in `docs/standards/srs-rotation.md`. |
| INFO-2 | DAS is effectively inert on a real tty: key repeat is slower than one byte per frame, and a byte-less frame reads as a release. Held movement runs at the kernel's repeat rate. Changing it is feel work for the console playtest. |
| INFO-3 | The remaining raw syscall numbers (read, ioctl, nanosleep, exit) were confirmed to translate correctly on aarch64 under qemu, and were left alone because the agnos stdlib names no ioctl number. |
| INFO-4 | A process killed by an external signal leaves the terminal raw. Keyboard signals cannot arrive in raw mode, so this needs an outside `kill`. |
| INFO-5 | Allocation failure is unchecked, but all allocation happens at startup and totals well under 1 MB. |
| INFO-6 | `CLAUDE.md` says `var buf[N]` is always N bytes. A top-level array has been N×8 since Cyrius 6.4.10. Harmless here (`orig_termios` is just larger than needed), but the rule is out of date. |

## Not exercised

Neither the real framebuffer nor the sound card was driven: this session had
no permission on `/dev/snd`, and writing to `/dev/fb0` could have disturbed the
display. The framebuffer's refusal paths and geometry are tested, but a real
blit, the busy-device path and the by-ear checks still want a console session.

## Verification

After the repairs: `cyrius fmt --check`, `cyrius lint` and `--strict` clean,
`cyrius vet` 17 deps, 0 missing, `cyrius audit` exit 0, `cyrius test` 340 / 0
(277 before), and the same suite passing on aarch64 under qemu. The fuzz sweep
is clean over 8,000 seeds (16,000 games), and over its default sweep with bounds
and poison enabled. The pseudo-terminal drive passes all ten checks, including
terminal modes restored on exit. The headless smoke's output and PPMs are
byte-identical to 0.6.1 over five seed / frame pairs, so the piece stream and
the gravity-only simulation did not change. DCE binary 80,832 → 81,096 B.
Benchmarks are flat over four interleaved pairs.
